      05 — what's guaranteed

      Borrowed from the big booking systems,
      sized for one clinic

      We don't need Airbnb's Kafka or Agoda's supplier caches — but the correctness ideas are the same ones.

      🔒

      No double-booking, ever

      Unique index (dentist_id, date, time) — the database itself refuses a second booking, not just the app.

      ⏱️

      Holds expire by themselves

      Every read filters on expires_at — an abandoned hold frees the slot with no cleanup job.

      ↩️

      Cancelled = free again

      Availability only counts non-cancelled rows — cancel a booking and the slot reappears on the next read.

      🖥️

      Server checks everything

      The UI filters, but bookAppointment re-validates capability, shift, lead time and occupancy anyway.
